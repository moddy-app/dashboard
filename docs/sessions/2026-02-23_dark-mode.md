## Fonctionnalités ajoutées

### ThemeProvider (`components/theme-provider.tsx`)
- Implémentation officielle shadcn/ui adaptée au projet
- Stockage dans le cookie `moddy_preferences` via `setPreferences`/`getPreferences` (au lieu de `localStorage`)
- 3 modes : `system` (par défaut), `light`, `dark`
- `system` supprime la clé `theme` du cookie (cohérent avec la logique `language`)
- Applique la classe `.dark` sur `document.documentElement`
- Expose `useTheme()` hook

### Sélecteur de thème dans `/debug`
- Ajouté dans le header de la page debug, entre le sélecteur de langue et l'horloge
- Boutons Auto / Clair (Light) / Sombre (Dark)
- Style cohérent avec le sélecteur de langue existant
- Traduit en EN et FR

## Architecture technique

### Flux du thème
1. Au chargement : `ThemeProvider` lit `getPreferences().theme`
2. Si absent → `defaultTheme` (`system`) → détecte `prefers-color-scheme`
3. Si `light` ou `dark` → applique la classe correspondante sur `<html>`
4. Changement via `useTheme().setTheme(mode)` :
   - `system` → `setPreferences({ theme: undefined })` (supprime la clé)
   - `light`/`dark` → `setPreferences({ theme: mode })`

### CSS
- Les variables CSS `.dark` sont **déjà définies** dans `index.css` (depuis la configuration initiale shadcn)
- La custom variant Tailwind `@custom-variant dark (&:is(.dark *))` est déjà en place

## Décisions prises

- **Cookie plutôt que localStorage** : cohérence avec le système de préférences existant du projet (`moddy_preferences`)
- **`undefined` = system** : cohérent avec la logique de la langue (`undefined` = auto)
- **Sélecteur dans `/debug` uniquement** : conformément aux instructions (même approche que la langue)
