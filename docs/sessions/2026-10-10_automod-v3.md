# 2026-10-10 — Automod IA v3

## Objectif
Aligner le dashboard sur la nouvelle version de l'Automod IA livrée par le backend (branche backend `claude/quirky-newton-6zge0l`, contrat dans `docs/API_ENDPOINTS.md` §Module — Automod AI) : barème par infraction, infractions personnalisées, détecteurs `image_gore` et `profile`, assistant de presets, liste des profils en attente, libellés de catégories dans les cases.

Le contrat a été négocié en direct avec la session Claude du backend (questions/réponses par messagerie inter-sessions). Le code a été écrit par des agents Sonnet, orchestrés et relus par la session principale.

## Tâches accomplies
1. **Fondations** : types (`sanctions`, `infractions_perso`, catalogue, holds, check), suppression de `categories_desactivees`, cinq détecteurs, exemptions communes (les salons de `profile` restent `[]`), helpers d'ids et de barème, services `getAutomodCatalog` / `checkCustomInfraction` / `getProfileHolds`.
2. **Page en onglets** : Réglages / Barème / Infractions personnalisées / Profils en attente (`?tab=`), brouillon unique.
3. **Barème par infraction** : groupé par famille, Moddy (planchers en lecture seule) ou Personnalisé (4 crans + récidive), `action_profil` pour les infractions de profil, réinitialisation = suppression de la clé, écriture minimale.
4. **Infractions personnalisées** : depuis un modèle ou de zéro, contrôle `/infractions/check` (sauté si l'entrée est identique à celle enregistrée), suppression qui retire aussi le barème associé.
5. **Assistant Léger / Équilibré / Strict** : reproduit `preset_config` du bot et applique le résultat dans le brouillon.
6. **Profils en attente** : liste en lecture seule paginée.
7. **Cases** : libellé de catégorie (config + catalogue → `categorie_label` → id brut), pas de lien de message pour une sanction de profil.
8. **Erreurs** : nouvelles formes plates (`code`, `infraction_id`, `index`, `sanction_key`), 503 « non enregistré » ; `ApiError.body` expose le corps complet.
9. **Relecture** : comparaison stable du brouillon, assistant démonté en lecture seule, retry 503 sur la version courante, garde-fous du PUT, accessibilité.

## Décisions
- Les libellés du catalogue ne sont **pas** recopiés dans nos i18n : le backend les sert en 5 langues, régénérés depuis les locales du bot.
- L'assistant écrit dans le **brouillon** et ne sauvegarde pas : l'admin enregistre, et un 422 s'affiche au bon endroit.
- Un barème `perso:<id>` orphelin est retiré par le service avant le PUT (garde-fou contre le 422).
- `action_profil: hold` sur `profil_pseudo` n'est jamais proposé (liste fournie par le catalogue).

## Points ouverts
- Le lien « voir la case » des profils en attente utilise `case_id` (UUID) dans `?case=` : confirmé par le backend, `GET /cases/{identifier}` accepte la référence courte comme l'UUID.
- Les badges d'état affichent Actif / Arrêté + Simulation ; le « À configurer » passe par l'avertissement `missing_notify_channel`, pas par un badge dédié.
- Le panneau des profils en attente n'affiche une erreur de rechargement que si la liste est vide.
- Rien n'a été testé dans un navigateur (pas de backend accessible) : `npm run build` et ESLint sur les fichiers touchés passent.
- `package-lock.json` est désynchronisé de `package.json` (`npm ci` échoue) : problème préexistant, non traité.
